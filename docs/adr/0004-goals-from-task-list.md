# 0004. Take public goals from Claude's task list

- Status: accepted
- Date: 2026-11-08
- Deciders: Valery Melou

## Context and problem statement

For public projects, visitors should see what Claude is working on ("Building the paywall screen"). Prompts and file names are private by default and far too revealing. Where can a short, human-readable goal come from safely?

## Decision drivers

- Free text is the riskiest thing Hivefloor sends; it must be short, opt-in and filtered.
- The goal should describe intent at a useful level, not raw activity.
- No extra work for the owner during a session.

## Considered options

1. The subject of the task Claude marks in progress in its task list (`TaskCreate` / `TaskUpdate`, with `TodoWrite` as a fallback).
2. The first line of the user's prompt.
3. A summary generated by a model.
4. A goal the owner types manually.

## Decision outcome

Chosen option: **the in-progress task subject**, because Claude already writes short, intent-level task titles, and they change as work progresses. The CLI records each task's subject when it is created and sends it as the goal only when `TaskUpdate` marks that task in progress, and only in public repos. It is cut to 60 characters, stripped of control characters and links, dropped if it contains a blocked word (security, vulnerability, CVE, exploit, token, secret, password, credential, plus custom words) or starts with `[private]`.

### Consequences

- Good: no prompts leave the machine; goals are naturally short and descriptive.
- Good: owners can opt out per task (`[private]`), per word list, or temporarily with `hivefloor pause`.
- Bad: depends on Claude Code's task tools, whose payload field names must be confirmed from recorded payloads in M2.
- Bad: sessions that don't use a task list show no goal; that is acceptable.

## More information

- PRD: CLI requirement C7, hardening rule H2, decision "Task-list tools" (Claude Code v2.1.142 and later).
